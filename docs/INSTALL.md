# 安装与升级

## 新安装

在 AstrBot 插件管理中使用仓库链接安装，或将源码放入 `data/plugins/astrbot_plugin_classnote/`。确保 `main.py` 直接位于该目录，不要嵌套两层文件夹。

在运行 AstrBot 的同一 Python 环境安装 `requirements.txt` 后重载。0.3.1 最低要求为 AstrBot 4.20、Python 3.11，同时需满足 AstrBot 自身的 Python 版本要求。管理页已在具备新版页面接口的 4.28.2、4.29.3 加载验证；4.20.0 使用 QQ 指令与未来任务，跳过管理页。运行插件无需 Node.js、前端构建或额外网页端口。

## 从 0.3.0 升级

在 AstrBot 插件列表更新课笺至 **v0.3.1** 后重载，原有课表和投递记录继续使用。若 0.3.0 处于加载失败状态，也可直接覆盖升级；无需删除数据库。已修复最低版本过高、页面接口缺失导致插件加载失败，以及调度接口缺失时无提醒的问题。

## 从 0.2.0 升级

1. 确认 AstrBot 至少为 4.20；如需管理页，使用具备新版页面接口的版本（已验证 4.28.2、4.29.3），再更新课笺并重载。
2. 进入“插件 → 课笺 → 课表管理”，已有课表和投递记录自动保留。
3. 新增调度配置默认使用 `future_tasks`，会生成“课笺 ·”开头的原生一次性任务。
4. 在“提醒计划”核对时间、投递地和开关。若希望保留原轮询方式，在“插件设置”改为 `polling`。
5. 新增视图目录和视图名称元数据需要重载插件；旧界面缓存可刷新页面。

已有提醒数据仍在同一 SQLite 数据库中，新版本仅增加原生任务映射和投递详情字段。升级后不要同时运行两份课笺实例。

默认只开放管理员私聊。QQ 官方适配器的账号标识可能不是普通 QQ 数字号，管理员 ID 以 AstrBot 事件或管理界面为准。

## 导入与核对

1. 在 WakeUp 选择“导出为日历文件”。
2. 将 `.ics` 作为文件附件发送到需要提醒的 QQ 会话。
3. 核对导入回复的课次、日期范围、时区和提前提醒来源。
4. 用 `/课表 下次` 检查计划，再用 `/课表 测试` 检查主动投递和人格。

若直接发文件无回应，先发送 `/课表 导入日历`，两分钟内再发文件。若仍无法读取，检查适配器是否提供 File 消息段，及 AstrBot 能否访问 NapCat 的附件地址。

也可在 `/课表 导入日历` 后粘贴完整 `BEGIN:VCALENDAR...END:VCALENDAR` 文本。平台长消息限制可能截断日历，因此优先用附件。插件不接受聊天中给出的服务器本地文件路径。

## 从 0.1.0 升级

1. 停用 `astrbot_plugin_wakeup_reminder`，停止它的后台提醒。
2. 安装新插件 `astrbot_plugin_classnote`。
3. 新数据库不存在时才会复制旧数据库，不会覆盖已有新数据。
4. 核对新插件的管理员、群聊、模型与备用开头设置；配置文件不自动迁移。
5. 在原会话中执行 `/课表 状态` 和 `/课表 下次`。

原数据库仍保留，不要同时开启新旧插件。旧订阅的提前量视为自定义设置，避免被 ICS 闹钟意外覆盖；想沿用日历值时执行 `/课表 提前 日历`。

## 常见情况

| 情况 | 处理 |
| --- | --- |
| 导入后不提醒 | 检查是否暂停、是否有未来课程、QQ 是否允许主动发言 |
| WakeUp 改课后还是旧安排 | 重新导出并发送；文件是快照 |
| 提示无限重复 | 在日历来源设置学期截止日期后重新导出 |
| 新学期保留旧停课 | 对相应日期“恢复”，或删除订阅后重新导入 |
| 开头像系统通知 | 核对会话人格与模型；模型异常时会使用备用开头 |

测试接口成功不代表 QQ 已读。实际部署请留一门即将上课的课程观察。
