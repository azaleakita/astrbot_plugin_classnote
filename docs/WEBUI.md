# 课表管理与未来任务

## 打开页面

使用支持新版插件页面接口的 AstrBot（已验证 4.28.2、4.29.3），更新课笺并重载。在 WebUI 的“插件”中打开课笺详情，选择“课表管理”。AstrBot 扫描 `views/classnote/index.html`，并读取 `.astrbot-plugin/i18n/` 中的视图名称；侧边栏视图分组与置顶方式由 AstrBot 控制。

页面没有独立登录、端口和前端构建步骤。通过 AstrBot 注入的 `AstrBotPluginView` / `AstrBotPluginPage` bridge 调用课笺 API，不能将 HTML 单独打开当成完整服务。

## 第一次导入

1. 在希望接收提醒的 QQ 私聊或群里先与 bot 对话。
2. 进入课表管理，点击“导入课表”。选择已有课表可替换，或选择“添加到其他 QQ 会话”。
3. 选择会话，填写持有者账号标识和称呼；群聊账号用于 @ 本人。QQ 官方适配器可能使用非普通 QQ 数字标识，请按实际账号填写。
4. 选择日历文件、分享文本或 WakeUp 备份。日历最大 2 MiB，也可粘贴完整日历文本。
5. 点击“预览课表”，核对范围、课次、投递地与提示，再确认导入。解析失败不会替换旧课表。
6. 在课表总览点击“发送测试”，明确确认后会向目标 QQ 会话真实投递；模型开启时可能产生 API 调用。

新会话列表最多读取最近 500 个对话的标识及标题，不读取聊天历史。列表未显示时可先通过 QQ 附件导入，页面中即可选中该课表。

## 课程与提醒设置

- 总览可按周翻页；空白日代表无课。页面按所选课表时区显示。
- “提醒设置”可原子保存提前量、日历闹钟来源、单课表开关。教学周课表还可以校准开学周一；真实日期日历不整体平移。
- “停课 / 调课”作用于整天。调课只替换实际日期，不自动取消参照原日期；恢复会移除该日覆盖。
- “导出 ICS”包含实际课程和当前生效的提前量，应用停调课安排；不写入 QQ 账号、聊天记录和模型配置。导出最多 2000 个展开课次、550 天、2 MiB，可重新导入。空课表或超限时请修正后重试。
- 删除课表会清理它的正式投递记录和所管理的任务，需要在页面再次确认。

## 任务需求与设置同步（0.4.0）

1. 在“插件设置 → 熟悉的语气”填写“未来任务需求模板”，保存即同步已有任务。
2. 使用 `{nickname}`、`{course}`、`{date}`、`{start}`、`{end}`、`{room}`、`{lead}`、`{timezone}`，不支持属性访问或格式化指令。模板最多 2000 字，字面花括号写作 `{{` 和 `}}`。
3. 在“提醒计划”展开任务需求预览，点击“编辑需求”可为单次提醒设置独立文本，最多 4000 字。独立文本不展开占位符；勾选“恢复跟随全局模板”即可恢复统一设置。
4. 在原生“未来任务”编辑需求同样有效，课笺会保留它并实际用于人格生成。只修改需求时保留原任务 ID 和开关；全局模板不会覆盖单条自定义。
5. 默认提前量更新会同步未设置个人提前量的课表，日历闹钟仍优先。在课表提醒设置选择“跟随插件默认设置”可明确覆盖日历闹钟。
6. 全局时区同步已有课表和任务。日历按真实时刻显示在新时区，去重键保持稳定；教学周课表按新时区重新计算。

需求指导提醒开头的语气与内容，不把任务改成可调用工具的主动 Agent；准确课程详情仍由程序追加。关闭人格生成时使用备用提醒开头。管理页保存后立即同步；后台每 10 秒检查默认值，每 30 秒核对任务。更改提前量会替换相应排期，需求编辑保留单次暂停与删除偏好。

## 原生任务的生命周期

`future_tasks` 使用 AstrBot 公开 `add_basic_job` / `update_job` / `list_jobs` / `delete_job` 接口。先建立禁用的基础任务，再设为带 `run_at` 的一次性任务后启用，避免创建过程中误触发循环计划。

每项任务包含插件所有者标记、课表 ID、生命周期标识、修订号和提醒去重键；执行时重新读取当前课表并验证课程仍有效。任务回调与轮询都进入同一套投递流水，课程详情由程序拼接，开头读取会话当前人格。

| 情况 | 处理 |
| --- | --- |
| 正常触发 | 校验时间和权限，持久化领取提醒，生成开头后再次校验并投递 |
| 发送失败 | 原生一次性任务被移除；补发窗口内重建带退避时间的任务，最多 3 次 |
| 课表改动 | 更新仍有效任务的修订信息，移除无效排期并安排新的课次 |
| 原生页暂停任务 | 同步时保留该任务的开关，插件重载后也保留 |
| 原生页删除任务 | 保存删除标记，不自动撤销用户操作；可明确要求重新生成 |
| 重载 / 卸载 | 清理课笺回调任务；启用时通过公开 API 重新注册，保留有效暂停偏好 |
| 切到轮询 | 清理课笺原生任务，沿用同一投递记录 |
| 关闭全局提醒 | 清理排队任务，但保留课表；执行前也会复核全局开关 |
| 人格或模型变更 | 后续提醒使用目标会话新的有效配置 |

基础任务不经过主动 Agent 的工具推理，不要求开启聊天中的“未来任务”工具；由课笺调用人格生成与主动消息 API。请勿在原生任务编辑器中修改其时间和负载，相关变更应在课笺中完成。原生“立即执行”不会绕过课笺的到时校验；检查投递请使用课笺的“发送测试”。

预排范围为未来 7 天，默认每 30 秒续排；最多每张课表 200 项、全局 1000 项。页面约每 30 秒刷新一次；编辑表单或弹窗打开时暂停刷新，防止覆盖输入。服务器需持续在线，短时恢复只补发配置窗口内且未上课的提醒。

## 排查

| 现象 | 核对 |
| --- | --- |
| 视图未出现 | 核对 AstrBot 版本、插件启用状态和完整文件结构，重载插件并刷新详情 |
| 页面显示未连接 | 从 AstrBot 内打开视图，勿直接打开 HTML；检查 WebUI 与核心版本是否匹配 |
| 无可选会话 | 先在对应 QQ 会话对话，确认平台在线；也可先通过 QQ 导入 |
| 未来任务列表为空 | 核对全局 / 单课表 / 群聊开关、课程是否在预排窗口、同步错误和手动删除标记 |
| 任务没有消息 | 查看投递记录、平台连接与主动消息权限，使用明确确认的测试提醒验证 |
| 修改后未生效 | 查看页面顶部同步错误；点击“同步未来任务”，或检查 AstrBot 日志的 `[classnote]` 记录 |

管理页拥有 Dashboard 管理员的管理范围，不用于向普通 QQ 用户暴露其他人的课表。课笺不会清理、修改或运行没有课笺所有者标记的原生任务。

实现依据：[官方插件视图文档](https://docs.astrbot.app/dev/star/guides/plugin-pages.html)、[官方调度器源码](https://github.com/AstrBotDevs/AstrBot/blob/master/astrbot/core/cron/manager.py)。

### 0.3.1 兼容行为

最低支持 AstrBot 4.20。旧版缺少 `astrbot.api.web` 时只跳过管理页，不影响 QQ 课表指令和课程提醒；可通过 `/课表 状态` 查看页面诊断。未来任务接口缺失时自动使用轮询，接口就绪后自动续排，管理页显示实际调度模式。重载会清理本插件注册的页面接口。
